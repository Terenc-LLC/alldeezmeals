# Handoff: ALLDEEZMeals — Today v2 + Planning Meals Recipe Card v2

## Overview
This is a **readability and intentionality design pass** on two existing screens.
No new features were added and no data model was removed — this is purely structure,
hierarchy, and visual treatment. The changes are surgical and targeted.

## About the Design Files
The files in this bundle are **design references created in HTML/React-via-Babel** —
prototypes showing intended look and behaviour, not production code to copy directly.

The task is to **recreate these designs in `src/App.tsx`** using the codebase's established
patterns: Lucide icons, Tailwind utilities where appropriate, and the CSS custom-property
tokens already in `src/index.css`. The prototypes use a small set of `wm-*` CSS utility
classes from `assets/warm-market.css`; the equivalent values are all present in
`src/index.css` already (same token names, same hex values).

## Fidelity
**High-fidelity.** Final colours, typography, spacing, radii, and interaction states are
all specified below and visible in the reference HTML files. Recreate to match.

## Codebase context
| Item | Detail |

### 1.2 GATHER — two groups

The ingredient list is split into two named groups. When `prepared` is empty, render a
single flat list with no group headers (existing behaviour).

**Data shape addition** — add a `prepared` boolean to each ingredient:
```ts
interface RecipeIngredient {
  // … existing fields …
  prepared?: boolean; // true = made in a prior meal, not a raw ingredient to gather
  pantry?:   boolean; // true = likely already in the pantry (check/restock reminder)
}
```

The meal-gen prompt should flag `prepared: true` on any ingredient that is a carry-over
from a prior day's recipe (e.g. leftover pulled chicken, cooked rice, batch-made sauce).

**Rendering logic:**
```
const preparedItems  = ingredients.filter(i => i.prepared)
const remainingItems = ingredients.filter(i => !i.prepared)
const hasPrepared    = preparedItems.length > 0
```

**Progress count** spans both groups combined:
```
gathered.size  /  (preparedItems.length + remainingItems.length)
```
Label: `{gatheredCount} of {totalIng} gathered` — `--t-caption-*`, `--c-text-muted`,
right-aligned next to the "GATHER" section label.

## Screen 2 — Planning Meals recipe card v2

**Reference file:** `ALLDEEZMeals Planning Recipe Card.html`  
**Component source:** `frames/planning-v2.jsx` (self-contained reference)

### What changed
1. **Ingredient list** — replaces crammed pill row with a readable three-column layout
2. **Steps** — replaces wall of text with numbered, spaced list
3. **Navigation** — one card at a time with a day-rail; prev/next in card header
4. **Purchase info** — each ingredient shows its shopping context (buy / reuse / staple)

### 2.1 Data shape additions

```ts
interface RecipeIngredient {
  // … existing fields …
  purchaseType?: 'buy' | 'reuse' | 'staple';
  purchaseNote?: string;  // e.g. "buy: 30 ct pkg", "reuse: from Thu", "staple"
}
```

Add to the meal-gen prompt: for each ingredient, determine whether the user needs to
**buy** it this week, whether it is **reused** from another day's purchase or batch-prep,
or whether it is a **staple** auto-excluded from the shopping list.

## Interactions & Behaviour

### Today v2
- **Provenance note** is read-only (no interaction). Shown only when `recipe.provenance` is set.
- **GATHER progress** counts items in both groups together.
- **Checking a prepared item** behaves identically to checking a remaining item (same toggle).
- **Pantry badge** disappears when its row is checked.
- **Source note** (e.g. "Sat · in the fridge") disappears when its row is checked.
- All other Today behaviours (day rail, step tapping, footer, rating) are **unchanged**.

### Planning Meals v2
- **Day rail**: clicking a day pill jumps directly to that day's card and resets vote/save
  state for the new card.
- **Prev/Next in card header**: same as day rail navigation, ±1.
- **Next in actions row**: same as next arrow, advances by 1.
- **Thumbs up/down**: toggle (tap again to clear); mutually exclusive — setting one clears
  the other. Persist to the meal's stored data.
- **Recipe Box ★**: toggles save to Recipe Box. Persist.
- **Swap**: existing behaviour (opens swap flow / regenerates this day's meal).
- Transitions: `.15s` on `background`, `border-color`, `box-shadow`.

## State additions

### Today tab state
No new top-level state required. The `prepared` boolean on ingredients is data, not UI
state. The `gathered` Set already tracks all ingredients by index — add prepared items
to the same set (use their array index, offset by `preparedItems.length` if needed, or
use a stable key like `ing.id`).

### Planning / Meals tab state
```ts
const [activeMealIdx, setActiveMealIdx] = useState(0); // which card is showing
```
Per-card state (`vote`, `saved`) can live inside the `MealCard` component or be lifted
into the plan week array if you want persistence. Persist thumbs + saved to Supabase /
localStorage alongside the existing meal data.
